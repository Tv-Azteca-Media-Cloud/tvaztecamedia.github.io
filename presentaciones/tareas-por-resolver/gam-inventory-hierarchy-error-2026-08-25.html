Error de validación por redundancia jerárquica en Ad Units
Integración: inyección de targetedAdUnits · Bloque de segmentación de inventario
Error QA
Código de Error API
INVENTORY_UNIT_CANNOT_BE_TARGETED_IF_ANCESTOR_IS_TARGETED
Descripción del contexto Durante las pruebas de calidad (QA) en la integración de creación de propuestas, se identificó una interrupción en el servicio al intentar inyectar múltiples unidades de anuncio (targetedAdUnits) en el bloque de segmentación de inventario. El sistema de Google Ad Manager rechazó la petición lanzando un error de ancestro.
🔍 Análisis y Causa Raíz
ROOT
Regla de negocio GAM — ancestro y descendiente no pueden coexistir en el mismo request
includeDescendants: true · Segmentación simultánea padre + hijo
Regla GAM
Causa raíz No es posible segmentar simultáneamente a una unidad de anuncio descendiente y a su ancestro directo en el mismo request. Cuando la integración envía includeDescendants: true, la API asume que el hijo ya está implícitamente incluido al apuntar al padre o abuelo. Si además se envía el ID del hijo de forma explícita, GAM detecta la redundancia y rechaza la petición.
Jerarquía de inventario de prueba
📦 Kapup Test Network  Nivel 1 · Abuelo · Red completa
📁 Kapup  Nivel 2 · Padre
📄 NivelTop  Nivel 3 · Hijo
Escenario de fallo
Al apuntar a "Kapup Test Network" (o "Kapup") con includeDescendants: true, el hijo "NivelTop" queda implícitamente incluido.

Si el payload también envía el ID de "NivelTop" de manera explícita, la API detecta la redundancia jerárquica y lanza:
INVENTORY_UNIT_CANNOT_BE_TARGETED_IF_ANCESTOR_IS_TARGETED
Comportamiento del payload 
// Payload problemático — envía ancestro + descendiente en el mismo bloque:
- targetedAdUnits: [
-   { adUnitId: "kapupTestNetwork", includeDescendants: true },  // Nivel 1 (Abuelo)
-   { adUnitId: "nivelTop",         includeDescendants: true }   // Nivel 3 (Hijo) ← CONFLICTO
- ]

// Payload válido — solo el nivel más alto deseado en la jerarquía:
+ targetedAdUnits: [
+   { adUnitId: "kapupTestNetwork", includeDescendants: true }   // Nivel 1 (Abuelo) — incluye todo
+ ]
✅ Resolución y Buenas Prácticas
FIX
Reglas de integración para evitar colisión jerárquica en producción
Aplicable al bloque targetedAdUnits de cualquier request de segmentación de inventario
Documentado
Regla 1
Enviar solo el ID del nivel más alto deseado.
Si se segmenta a un nodo padre o abuelo con includeDescendants: true, eliminar del payload todos los IDs descendientes directos. El sistema GAM los incluye implícitamente.
Regla 2
Múltiples IDs solo si son ramas independientes ("hermanos").
Es válido enviar varios IDs en el mismo request únicamente si estos operan como nodos del mismo nivel sin relación padre-hijo entre sí (e.g., dos hijos distintos de un mismo padre, sin incluir al padre).
Validación recomendada
Antes de construir el payload de targetedAdUnits, la integración debe verificar que ningún ID en la lista sea ancestro de otro ID de la misma lista. Si se detecta esa condición, conservar solo el ID del nivel más alto y eliminar a sus descendientes del array.
Ejemplo correcto (hermanos) 
// Válido — "Kapup" y otro nodo hermano sin relación padre-hijo entre ellos:
+ targetedAdUnits: [
+   { adUnitId: "kapup",      includeDescendants: true },  // Hermano A
+   { adUnitId: "otroNodo",   includeDescendants: true }   // Hermano B (rama separada)
+ ]
