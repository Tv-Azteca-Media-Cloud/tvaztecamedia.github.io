BUG #7
DUPLICATE_VALUE en TVAI_IdExterno__c tras UPDATE_LINE_ITEMS exitoso
DmlException · Log: apex-07LWG00000sttT02AI · GAM HTTP 200 recibido, falla en DML post-callout
Pendiente
Archivo crp-integrations/main/default/classes/TVAI_GAMSoapIntegrationHelper.cls ~líneas 517–559 (método updateLineItem)
Error
DmlException: Update failed. First exception on row 0 with id 802WG00000dtXzYYAU; first error: DUPLICATE_VALUE, duplicate value found: TVAI_IdExterno__c duplicates value on record with id: 802WG00000du2qHYAQ
Contexto GAM respondió HTTP 200 con updateLineItemsResponse exitoso — el Line Item 7400373780 fue actualizado en GAM correctamente.

Sin embargo, el método updateLineItem (post-procesamiento del response) intenta escribir TVAI_IdExterno__c = "7400373780" en el OrderItem del amendment (802WG00000dtXzYYAU).

El OrderItem original (802WG00000du2qHYAQ) ya tiene ese mismo valor en TVAI_IdExterno__c — fue escrito cuando createLineItems corrió por primera vez. El unique constraint explota.
Root cause updateLineItem fue diseñado para el flujo CREATE_LINE_ITEMS (donde estampar el ID nuevo es correcto). También se invoca como callback de UPDATE_LINE_ITEMS, pero en ese caso el Line Item ID no cambia — ya existe en el OrderItem original.
Fix 
// Método updateLineItem (~línea 550), bloque de actualización DML:

// ── ANTES ─────────────────────────────────────────────────────────────────
- if (hasChanges) {
-     Database.update(patch, AccessLevel.SYSTEM_MODE);
- }

// ── DESPUÉS ───────────────────────────────────────────────────────────────
+ if (hasChanges) {
+     try {
+         Database.update(patch, AccessLevel.SYSTEM_MODE);
+     } catch (DmlException e) {
+         Boolean isDuplicate = e.getMessage() != null
+             && e.getMessage().contains('DUPLICATE_VALUE')
+             && e.getMessage().contains(EXTERNAL_ID_FIELD);
+         if (!isDuplicate) {
+             throw e;
+         }
+         // DUPLICATE_VALUE en TVAI_IdExterno__c: el GAM Line Item ID ya está
+         // en el OrderItem original. El update de GAM fue exitoso; no-op.
+     }
+ }
Impacto real
El amendment sí llegó a GAM (HTTP 200). El único problema es que Salesforce no registra la excepción de DML como no-fatal — propaga hacia arriba y marca el fulfillment como fallido, aunque GAM esté actualizado. El fix hace que ese DML duplicado sea silenciado.
BUG #6
Amendment envía GAM Order ID en lugar del GAM Line Item ID
CommonError.NOT_FOUND → resuelto · Log confirmación: apex-07LWG00000sttT02AI · GAM HTTP 200 ✅
Desplegado
Archivo crp-integrations/main/default/classes/TVAI_GAMSoapIntegrationHelper.cls líneas 371–389
Error GAM
CommonError.NOT_FOUND @ lineItem[0].id; trigger:'4164647756' // GAM recibe el Order ID (4164647756) en lugar del Line Item ID (7400373780)
Root cause El método generateUpdateLineItemsSoapRequest hace SOQL sobre OrderItem.TVAI_IdExterno__c. Ese campo contiene el GAM Order ID (4164647756). El GAM Line Item ID (7400373780) vive en AdOrderItem.AdServerOrderLineIdentifier. GAM rechaza el request porque 4164647756 es un Order ID, no un Line Item ID.

Contexto confirmado por el usuario:
  • AdOrderItem: 802WG00000dtXzYYAU
  • Ad Server Order Line Identifier = 7400373780 ✅ (Line Item ID — valor correcto)
  • Ad Server Order Identifier = 4164647756 ❌ (Order ID — valor que se estaba enviando)
Cambio 
// Método: generateUpdateLineItemsSoapRequest (~línea 371)

// ── ANTES (incorrecto) ────────────────────────────────────────────────────
- List<SObject> rows = Database.queryWithBinds(
-     'SELECT TVAI_IdExterno__c FROM OrderItem WHERE Id = :orderItemId LIMIT 1',
-     new Map<String, Object>{ 'orderItemId' => orderItemId },
-     AccessLevel.SYSTEM_MODE
- );
- String gamLineItemId = rows.isEmpty() ? null : (String) rows[0].get(EXTERNAL_ID_FIELD);
- if (String.isBlank(gamLineItemId)) {
-     throw new TVAI_GAMSoapIntegrationException(
-         'El OrderItem ' + orderItemId + ' no tiene GAM Line Item ID (TVAI_IdExterno__c vacío)'
-         + ' — debe ejecutarse CREATE_LINE_ITEMS primero.'
-     );
- }

// ── DESPUÉS (correcto) ────────────────────────────────────────────────────
+ List<SObject> rows = Database.queryWithBinds(
+     'SELECT ' + AD_SERVER_ORDER_LINE_ID_FIELD
+     + ' FROM ' + AD_ORDER_ITEM_OBJECT
+     + ' WHERE ' + AD_ORDER_ITEM_ORDER_ITEM_FIELD + ' = :orderItemId LIMIT 1',
+     new Map<String, Object>{ 'orderItemId' => orderItemId },
+     AccessLevel.SYSTEM_MODE
+ );
+ String gamLineItemId = rows.isEmpty() ? null
+     : (String) rows[0].get(AD_SERVER_ORDER_LINE_ID_FIELD);
+ if (String.isBlank(gamLineItemId)) {
+     throw new TVAI_GAMSoapIntegrationException(
+         'El AdOrderItem del OrderItem ' + orderItemId
+         + ' no tiene GAM Line Item ID (AdServerOrderLineIdentifier vacío)'
+         + ' — debe ejecutarse CREATE_LINE_ITEMS primero.'
+     );
+ }

BUG #4
goalType DAILY incompatible con lineItemType STANDARD
Regla de negocio GAM · Log: apex-07LWG00000sse4i2AA
Pendiente
Error GAM
ReservationDetailsError.DURATION_NOT_ALLOWED @ lineItem[0].primaryGoal.goalType; trigger:'DAILY'
Root cause GAM prohíbe goalType=DAILY con lineItemType=STANDARD. DRO está enviando goalType: "Daily" + lineItemType: "STANDARD". El Apex traduce fielmente lo que DRO manda — el problema está upstream en la configuración del catálogo/producto.
Origen UI Quote → Entrega → Goals → campo "Impression Limit: Diario". Ese campo fuerza goalType=Daily.
Reglas GAM
Combinaciones válidas según GAM:
• STANDARD → LIFETIME (impresiones totales del vuelo)
• SPONSORSHIP → DAILY (% de tráfico, no impresiones)
• BULK → DAILY (impresiones diarias — posiblemente el tipo correcto para este caso de uso)

Acción requerida: confirmar con el equipo de catálogo/DRO qué tipo de producto corresponde a "impresiones diarias" y alinear lineItemType en consecuencia.
Área Configuración de catálogo / DRO — no requiere cambio de código Apex
