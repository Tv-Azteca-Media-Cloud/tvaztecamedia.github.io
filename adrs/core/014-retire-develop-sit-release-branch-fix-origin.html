ADR-014 Accepted Core Layer
Retire develop-sit; Release Branches + Immutable Tags Are the Fix Origin
TV Azteca · Salesforce Delivery Platform · ADP Whitelabel
Fecha: 2026-07-22 Estado: Accepted Layer: Core / Base Template
Context

develop-sit was introduced (RM-RUNBOOK, docs/sit-bugfix-process/) as a permanent branch that "represents what is currently deployed to SIT" and serves three purposes: the base for sprint-delta calculation, a single ref for "what's in SIT right now," and the origin of SIT-bugfix branches (bugfix/sit/<squad>/<id>).

By 2026-07-22 that construct collides with the project's own governance and with reality:

  1. It is an environment branch — an explicitly recorded anti-pattern. SOUL.md: "No environment branches: Branches are not databases — they cannot represent sandbox state. Pipeline mechanics must never depend on per-environment branches." CICD.md lists the same under Branching Anti-Patterns and warns environment branches "go out of sync exponentially under parallel releases." develop-sit is precisely "the branch that equals SIT." It also does not appear in the canonical branch table in CICD.md (main, release/*, develop, develop-rXXX, feature-rXXX/*, hotfix/*) — it is a project-local addition the template model never sanctioned.
  2. Parallel releases break the single-pointer premise. From the moment R2-s6 is promoted to SIT, R1 is still in UAT (Go-Live 2026-07-25) while R2 owns SIT. A single develop-sit can point at only one of the two live tracks — exactly the "out of sync under parallel releases" failure the docs warn about. CICD.md already assigns parallel-release scaffolding to "the project that adopts the template"; this ADR is that scaffolding.
  3. The tooling is already tag-based; the doc claim is stale. scripts/generate-sprint-manifest.js requires --base-tag (canonical) or --base (alias) with no fallback to develop-sit (line 46). The RM-RUNBOOK claim that the script "uses develop-sit as --base by default" is false today. The delta baseline is already an immutable tag, not the environment branch.
  4. The apparent "drift" was a tag-placement bug, not a mirror failure — but it proves the same point. Investigation on 2026-07-22 (git ancestry + GitHub Actions run history) established what was actually deployed to SIT and reconciled the tag confusion:
  • SIT holds v1.0.0-rc.34 (82e13778) — the tip of release/r1, and the only recent R1 tag that landed on a release branch rather than on develop HEAD.
  • release/r1-s5 (caf7ca7) descends cleanly from rc.34 (+3 admin-profile cleanup commits, PRs #453/#448/#447) and is artifact-identical to SIT — zero diff across releases/r1/. It is a strict superset of the SIT state, missing nothing.
  • v1.0.0-rc.35 (77fc1ee) is a develop commit, not the SIT artifact. It was never deployed to SIT. It only looked like "the last RC cut from develop-sit" because of the bug below.

The confusion originated in releaseCreateManual.yml: gh release create was invoked without --target, so every tag defaulted to the repository default branch (develop) HEAD instead of the commit that was actually built from inputs.ref. rc.31, rc.32, rc.33, and rc.35 all landed on develop; only rc.34 (built before the pattern) sits on the release branch. So the tags did not mark the artifacts they named — the ledger of "what's in SIT" was decoupled from the git tags. That is precisely the environment-branch / floating-pointer failure this ADR retires: the fix is to anchor to a release branch + a tag that is guaranteed to point at the built commit (workflow bug fixed 2026-07-22; see Follow-up #2).

A fix is authored against a release artifact, not against a stage. Which sandbox currently hosts that artifact (SIT, UAT, PreProd) is irrelevant to where the fix branches from. Anchoring the fix line to the release makes it robust to which environment holds the artifact and to parallel tracks.

Decision

Retire develop-sit as the SIT baseline construct. The origin for any fix to promoted work is the per-sprint release branch (release/rN-sX) and its immutable release tag (vX.Y.Z-rc.N) — never a branch that tracks an environment.

What "retire" means here
  • develop-sit is kept, not deleted. The ref remains for history and for the CI wiring that still references it (see Follow-ups). It simply stops advancing — it is no longer repositioned on sprint close and no longer originates bugfix commits.
  • release/r1-s5 is created at develop-sit's state on retirement (caf7ca7) as the properly-named, correctly-shaped anchor for any remaining R1 UAT bugfix — consistent with release/r2-s6. Verification (2026-07-22) confirmed it is artifact-identical to what is deployed to SIT (v1.0.0-rc.34 / 82e13778), descending from it by three admin-profile cleanup commits with zero releases/r1/ diff — so it is the correct converged R1 content, not a divergent one. The anchor tag (v1.0.0-rc.36) is minted on caf7ca7 by the fixed releaseCreateManual.yml (Follow-up #2), then promoted to SIT and UAT so rc.36 = release/r1-s5 = SIT = UAT.

Rules
  1. Fix origin = the release the artifact belongs to. A bug in what is in SIT/UAT for release rN is fixed off the newest release/rN-sX branch (equivalently its -rc.N tag). Within a release, SIT is overwritten each sprint, so "the rN line in a managed env" is always the latest sprint branch of rN.
  2. Anchor to the immutable tag for reproduction. Reproduce/build against the tagged artifact (vX.Y.Z-rc.N), not a floating branch tip, so "which sandbox state?" cannot re-enter by the back door. Where a stable state is untagged, tag it (once the correct commit is confirmed — see Follow-up #2) so every anchor is immutable.
  3. Backpromotion is unchanged and still mandatory. Same two-phase, same-SHA parity mechanic (git merge --no-ff) as before — only the Fase 1 base changes from develop-sit to the release branch. The fix must reach develop (and, for R1 during the R1/R2 overlap, the R2 track) so no line loses it. Backpromotion parity remains the invariant that keeps lines reconcilable (ADR-012, ADR-011).
  4. Per-sprint release branches are long-lived while their artifact is in a managed env. This reverses the earlier "cut, generate, dormant" expectation: a release/rN-sX branch remains the fix origin as long as its artifact occupies a managed environment.
Relationship to prior ADRs
  • ADR-010 (cumulative artifact promotion) is reinforced, not weakened: the unit of promotion and now of fix authorship is the immutable artifact.
  • ADR-012 (bugfix/hotfix lines) referenced "branched from develop-sit" for the R1 bugfix line. That phrase is superseded: R1 UAT bugfixes now branch from release/r1-s5. All ADR-012 containment controls (shared-sandbox scope, mandatory backpromotion, reconciliation deadline, dual approval for hotfix) stand unchanged.
  • ADR-011 (multi-track coexistence) anticipated per-track lines and bidirectional back-promotion; retiring the single environment pointer in favor of per-release branches is consistent with that direction.
Consequences

Positive

  • Removes a recorded anti-pattern (environment branch) and realigns with the canonical CICD.md branch model.
  • Survives parallel releases: R1 (release/r1-s5) and R2 (release/r2-s6) each have an independent, correctly-named fix origin. No single pointer to contend over.
  • Simplifies sprint close: step 4 was "reposition develop-sit to the deployed commit" (ambiguous under two tracks). It becomes "confirm the -rc.N tag" — nothing to reposition.
  • The delta baseline is immutable (a tag) instead of a mutable branch that could drift.

Negative / risks accepted

  • Release branches become long-lived, and "the rN line in SIT" means the newest sprint branch of rN — an operator must know that a post-S7 SIT bug is fixed off release/r2-s7, not release/r2-s6. Mitigated by documenting the rule in RM-RUNBOOK and the sit-bugfix process, and by the RELEASE-CALENDAR.md SIT Artifact column being the source of truth for "what's in SIT."
  • Docs and CI that reference develop-sit must be reconciled (see Follow-ups). Until then develop-sit remains load-bearing for the workflows below, so it is retired-in-place (kept), not deleted.
Follow-ups (bounded; not authorized by this ADR)
  1. CI + skill rewiring (deferred by RM, 2026-07-22). develop-sit is still load-bearing for:
  • .github/workflows/releaseCreateOnPush.yml (push trigger — the SIT-bugfix auto-build),
  • .github/sandbox-fleet.json (releaseRef) and .github/workflows/fleetResumeScheduled.yml,
  • the skills coupled to the above: create-bugfix-pr (Fase 1 base = develop-sit), sprint-close-sit (repositions develop-sit on sprint close), and provision-sandbox-fleet (releaseRef default).

These are intentionally not changed in this ADR's implementation. Until they are repointed, develop-sit must be kept and must still be repositioned on sprint close (so the residual auto-build path branches from the true SIT state). Repointing them — SIT-bugfix auto-build trigger → release branch; fleet releaseRef → an appropriate stable ref; skills updated to match — is a separate, later change. When it lands, the transition caveat in RM-RUNBOOK.md (Sprint close) and the banner in docs/sit-bugfix-process/README.md are removed.

  1. Anchor tag — RESOLVED (2026-07-22). The original worry ("rc.35 may be the true SIT state, don't tag caf7ca7 blindly") was investigated and dismissed:
  • What is deployed to SIT is v1.0.0-rc.34 (82e13778) — verified against the GitHub Actions run history and the sf builds deploy target in the run logs. It is the tip of release/r1.
  • caf7ca7 (= develop-sit tip = release/r1-s5) is artifact-identical to rc.34 (descends from it by 3 cleanup commits, zero releases/r1/ diff). So caf7ca7 is the correct converged SIT content, not a divergent branch.
  • v1.0.0-rc.35 (77fc1ee) was never deployed to SIT. It is a develop commit that only appeared to be "the last RC from develop-sit" because of the tag-placement bug in releaseCreateManual.yml (tags defaulted to develop HEAD — see Context #4). The single substantive artifact gap between caf7ca7 and UAT (rc.35) is one validation-rule member, Lead.TVAS_ValidaTransicionStatusPorAprobacion, confirmed to belong in R1 and present in the anchor.

Resolution. The releaseCreateManual.yml bug is fixed (--target "$(git rev-parse HEAD)" on gh release create, 2026-07-22) so future tags mark the commit they were built from. The R1 anchor tag v1.0.0-rc.36 is minted on caf7ca7 by the fixed workflow and promoted BLDREL → SIT → UAT, converging rc.36 = release/r1-s5 = SIT = UAT. The RELEASE-CALENDAR.md SIT Artifact column is updated to rc.36. No further verification is pending.
