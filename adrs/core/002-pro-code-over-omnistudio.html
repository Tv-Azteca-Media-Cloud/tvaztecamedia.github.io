ADR-002 Accepted Core Layer
Pro-Code (LWC + Apex) as Primary Extensibility Path
TV Azteca · Salesforce Delivery Platform · ADP Whitelabel
Fecha: 2025-01-01 Estado: Accepted Layer: Core / Base Template
Context

The Salesforce stack offers multiple extensibility options: OmniStudio (FlexCards, OmniScripts, Integration Procedures), Screen Flows, and pro-code (LWC + Apex). A common pattern in Salesforce projects is to treat low-code tools as the default and escalate to pro-code only when low-code fails. This project involves AI-assisted development, CI/CD pipelines, and version-controlled metadata — areas where that approach creates friction and introduces hidden complexity.

Decision

LWC + Apex is the primary extensibility path, not a fallback. The decision framework:

  • Custom screens and UI are built as LWC components. Screen Flows are not a substitute for LWC — a complex Screen Flow is never preferred over a well-structured LWC + Apex combination.
  • Business logic is implemented via the Trigger Action Framework (TAF) — one trigger per object, logic in discrete action classes. Flow is not used for complex validations, high-volume processing, or logic that benefits from unit testing. See ADR-008.
  • Flow is acceptable for simple, bounded, self-contained automation (field updates, simple notifications) where the logic is genuinely maintainable as a declarative artifact.
  • OmniStudio is a last resort, only when it brings a clear, justified benefit that LWC + Apex cannot provide.
Alternatives Considered
OmniStudio-first
Rejected — poor version control story, limited AI tooling support, unreadable metadata diffs, platform-specific debugging.
Screen Flow for complex CSR screens
Rejected — low observability, no unit testing, difficult to review in PRs, and tends to grow into unmaintainable declarative spaghetti.
Flow-first for business logic
Rejected — Flow is not designed for complex validations or high-volume scenarios where Apex provides reliability, testability, and governor limit control.
Consequences
  • All custom UI is in source control as LWC metadata, reviewable in PRs and deployable via CI/CD.
  • Apex code is fully unit-testable and covered by the CI pipeline.
  • When a developer proposes a Screen Flow for a non-trivial interaction, this ADR is the reference to escalate to LWC + Apex instead.
  • Platform configuration work (product catalog, pricing rules, Setup-based workflows) is unaffected — this decision applies to custom development only.
