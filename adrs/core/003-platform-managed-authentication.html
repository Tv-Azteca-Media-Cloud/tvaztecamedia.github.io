ADR-003 Accepted Core Layer
Platform-Managed Authentication for All Integrations
TV Azteca · Salesforce Delivery Platform · ADP Whitelabel
Fecha: 2025-01-01 Estado: Accepted Layer: Core / Base Template
Context

Integrations require credentials to authenticate against external systems (billing engine, network inventory, GIS, etc.). Handling credentials in code or configuration files introduces security risk, complicates rotation, and violates least-privilege principles.

Decision

No credentials are handled directly in code or configuration files. Authentication is always delegated to the platform:

  • Outbound integrations: use Named Credentials and External Credentials configured at the org level. Service accounts authenticate via JWT Bearer flow (certificate-based, no password).
  • Inbound integrations: external systems authenticate via the org's identity provider using OAuth flows configured at the Connected App level.

Secrets, tokens, and certificates live in the platform's secure credential store — never in Apex, never in metadata files, never in environment variables committed to source control.

Alternatives Considered
Hardcoded credentials in Custom Metadata / Custom Settings
Rejected — visible in source control, difficult to rotate, and a security audit failure point.
Storing tokens in Apex static variables or Custom Labels
Rejected — same risks as above, plus no audit trail on access.
Consequences
  • Credential rotation is a platform operation, not a code change.
  • Any new integration must define its Named/External Credential configuration before the first line of Apex is written.
  • CI/CD pipelines must include credential configuration as a deployment step for new environments.
